# Continuous Integration

GitHub 的 `.github/workflows/ci.yml` 在推送或 PR 目标为 `main` 时触发。
仅推送到 Gitee 不会触发 GitHub Actions。

## 当前任务

`test`（Ubuntu）：

```text
pnpm test
pnpm typecheck
pnpm release:check
pnpm build
```

`pnpm test` 包含 Core 测试、runtime staging 脚本测试以及桌面排序逻辑测试。
排序逻辑测试不是完整的桌面交互自动化测试。

`desktop-rust`（macOS）：

```text
pnpm desktop:sidecar:prepare
检查 sidecar 可执行文件、Core 入口和 node_modules
cargo check --manifest-path apps/desktop/src-tauri/Cargo.toml
```

CI 使用 Node.js 22、pnpm 10.17.1。仓库已提交 `pnpm-lock.yaml`，但当前 workflow
仍使用 `pnpm install --no-frozen-lockfile`；文档不将其描述为锁定依赖安装。

## Windows 与安装版验证边界

新增的 `windows-runtime` job 已还原，当前 workflow **没有 Windows runner**。
Windows 兼容代码和本地测试仍保留，但不能据此声称 Windows CI 或原生安装验证通过。
手动验证要求见 [Windows compatibility](36-windows-compatibility.md)。

此 CI 不执行完整 Tauri 安装包构建、安装后启动或真实 MCP 调用验证。
本地 UI 变更仍需完整打包，不能只替换 Core runtime。
